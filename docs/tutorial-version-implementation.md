# 教程正式版本：本次实现与验收

## 对评估稿的取舍

保留一篇 `article`、一个短链、同一份收藏/点赞/阅读/购买权益，新增 `article_edition` 指向追加的 `article_detail` 快照。版本只在章节正文内切换，目录和上下章仍沿用现有结构。整本专栏多目录版本留待实际需要时实施。

用户再次明确要求地址栏完全不变。因此 `edition_code` 用于展示；不创建 `?v=`、不改 history、不复制历史版直链；重新打开或刷新主地址始终进入默认版。已有评论通知 hash 仍可定位原线程，必要时页内切到其版本。

按用户最新反馈，界面只保留版本选择与对应评论，沿用站内橙色和现有组件。移除受众标签、引导卡片、更新说明、目录版本徽标和空讨论解释文案；既有说明字段保留在数据层。版本名称由作者填写。首次启用自动追加 **v1「启用时存档」**，保存当时线上原文；其时间表示本次归档时间。现有混合正文仍需作者人工拆分；本次没有读写生产数据库，也没有把旧留言自动归到任何版本。

**撤回当前版必须指定另一个公开版本。不能清空 `current_edition_id` 回滚**，否则旧代码的最大修订读取规则可能暴露草稿。

## 管理端入口与使用

在 `paicoding-admin` 原有“文章管理 → 文章编辑”中，继续使用原 Markdown 编辑器及预览：

1. 已上线文章点击“更新”，选择“发布新版本”，填写版本名称；编码自动递增。
2. 新版本发布后设为当前版。也可仅保存草稿；线上正文、目录时间及搜索内容不变。
3. 启用后，工具条可选择编辑某个版本。存在服务端草稿时加载草稿，修订发布后替换该版本的公开指针。切换发布方式只改发布设置，不重新加载编辑器正文。
4. 本地草稿按文章和编辑目标隔离。切换编辑版本时提示并保留未提交内容；重新进入相应版本可恢复。
5. “版本管理”以简洁列表提供设为当前版、撤回、编辑。撤回后保留正文和讨论，重新发布可恢复可见性。
6. 已有短链在导入 Markdown、Word、AI 初始化及保存时保持原值。版本发布只改正文、标题/摘要/封面与版本引导信息；分类、标签和权限沿用文章设置。

首次处理 `/react-vs-toolcall`：先在新版本中放入整理后的新版正文并发布默认，再选择 v1「启用时存档」，人工整理为干净的初版正文、修改版本名称后修订发布。原混合正文快照始终保留，旧留言先从“早期讨论”访问。

## 实际接口与读取规则

管理接口均要求 ADMIN（兼容 `/api/admin/article/` 和 `/admin/article/` 前缀）：

| 相对路径 | 方法 | 用途 |
| --- | --- | --- |
| `edition/list?articleId=…` | GET | 包含草稿/撤回状态的版本列表 |
| `edition/detail?articleId=…&editionId=…` | GET | 所选版本草稿优先的编辑内容 |
| `edition/save` | POST | `NEW_EDITION` / `REVISE_EDITION` / `SAVE_DRAFT` |
| `edition/default` | POST | 选择已公开默认版 |
| `edition/withdraw` | POST | 撤回；当前版需 `fallbackEditionId` |

写操作先锁 `article` 行，在同一事务内分配版本序号、追加正文、更新公开/草稿指针。修订需匹配 `expectedPublishedDetailId` 和 `expectedDraftDetailId`；首次启用需匹配当时的线上正文 ID。旧编辑保存入口与元数据快改不能绕过版本管理覆盖正文或更改短链。

页内切版 GET 原页面地址，使用 `X-Article-Id`、`X-Article-Edition`、`X-Article-Detail`、`X-Article-Switch: 1`。同一个 SSR 控制器继续执行教程可见性、登录/星球/付费阅读和试看逻辑；`queryFullArticleInfo` 在切版请求中只读足迹，不增加阅读计数。响应禁止缓存；客户端只解析惰性 HTML 片段，不执行其中脚本。

`ArticleEditionRequestFilter` 的 ThreadLocal 只在当前请求内传递选择，并在 `finally` 清除。普通首屏无请求头，读取默认公开指针。开启版本管理后不回退到 `MAX(version)`；搜索索引也只读取默认公开指针。正式版本事件在事务提交后刷新搜索及相关缓存，不重复奖励“首次发文”活跃分。

## 评论、划线与 AI

- 顶层评论必须提交阅读版本和公开正文快照；回复从根评论继承，不信任客户端另填的版本，不允许跨文章/伪造线程。
- 本版评论、热门评论、分页、划线均按正式版读取；历史讨论包括其他公开版和 `edition_id IS NULL` 的早期讨论。已撤回版不对外展示。
- 原始 `article_detail_id` 不随修订改变；同版重定位只更新 `HighlightDto.anchoredDetailId`，并校验页面正文未过期。
- AI 以已保存线程的原始公开快照构建上下文。早期讨论归属不明时只依据问题与引用，不代入新版；无全文权限时不将隐藏正文提供给 AI。
- 版本切换取消旧 AI 流，清理划线状态，重建目录和图片预览，使用请求序号避免旧响应覆盖新选择。评论草稿按版本隔离，滚动记录按版本和正文快照隔离。
- `/comment/api/context?commentId=…` 返回公开线程及其版本，供通知定位；不返回私有草稿正文。
